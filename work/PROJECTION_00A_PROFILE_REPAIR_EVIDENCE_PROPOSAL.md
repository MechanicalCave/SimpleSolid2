## Why this gate precedes Projection

The Owner raised a concrete unresolved design question: if an upstream Sketch gains or loses boundary entities, can an existing Profile be repaired and an existing Extrude continue while retaining durable identity, Undo/Redo and cold Save/Reopen semantics? A hypothetical Face topology change from four to six edges is **not** verified current SS2 behavior and must not dictate automatic Project Face membership refresh policy.

Present SS2 code provides:

- `src/part/include/simplesolid2/part/profile.hpp`: stable `ProfileId`; `ProfileRegionIntent` names Sketch `EntityId`s with boundary anchors; `resolveProfileRegionIntent()` refuses missing/unresolved intent instead of silently selecting similar geometry.
- `src/application/include/simplesolid2/application/document_session.hpp`: `ReplaceProfileRegionIntentCommand` and `EditExtrudeFeatureCommand`; commands explicitly carry `ProfileId` and `FeatureId`.
- `src/application/document_session.cpp`: Replace Profile validates one currently resolvable region, commits without inventing a new Profile; Edit Extrude validates the new Profile and requires a valid target evaluation.
- `src/part/profile_kernel_input.cpp`: Extrude consumes the currently resolved Profile; a missing/unresolved Profile returns structured failure.
- `tests/pm01c_feature_commands_test.cpp`, `tests/pm02f_stage_aware_profile_evaluation_test.cpp`, `tests/pm02h_face_supported_extrude_workflow_test.cpp` offer nearby regression patterns. **They are not proof that the entire new scenario was executed.**

## Explicit proposed Projection product contract — not activated

1. One Sketch tool, **Rzutuj geometrię / Project Geometry**, with all options in the **right-hand tool panel**, no modal dialog.
2. Selection modes **Edges** and **planar Face**, optionally combined in one staged selection session; one successful Finish = one authored Undo step. Preview/Cancel do not author.
3. Same-Part projection is **associative by default**: authored target Sketch entities reference strict upstream semantic sources; recompute materializes current exact 2D geometry. The source identity includes the correct `BodyStageRef` and `MaterialEdgeReference` or separately accepted Face-boundary identity. No provider token persistence and no guessed rebind.
4. **Regular** projected entities can participate in Profile and Extrude/Revolve; **Construction** projected entities are reference-only. Link state is independent of geometric role. Both can be used for snapping, dimensions and constraints subject to source-driven geometric degrees of freedom.
5. Linked geometry is visually distinct and has an explicit linked-state indicator in Properties; linked positions are source-driven, not freely dragged. **Break Link** preserves resulting geometry and stable `EntityId`, makes it local/editable, and preserves compatible constraints. Delete/Undo/Redo/Save/Reopen must be tested.
6. **Project Face** processes boundary edges of a selected **planar** Face including hole loops; supports only exact representable Line/Circle/Arc projection. **Unsupported geometric curve kinds are visibly skipped**, leaving partial/open Sketch geometry that the user can manually complete. Report count, reason and affected geometry; never silently close, tessellate or approximate.
7. **Source Missing/Ambiguous/stale identity or invalid capture context is not an 'unsupported curve' skip**; reject affected binding or whole operation per a separately accepted integrity policy. Do not let partial mode mask identity errors.
8. New Face boundary members produced by future upstream topology changes are **not automatically authored into Sketch v1**. Only existing strict linked identities recompute. Whether to add/remove members through explicit Refresh is deferred until the A0–A8 test results and a separate decision.
9. Future Assembly-context projection remains a **Part-owned snapshot**, without cross-document associative dependencies; it is not included in this first Part-local work item.
10. Exact curve support initially Line/Circle/Arc only; a tilted circle yielding ellipse is Unsupported. No polyline fallback or hidden tolerant substitutions.
