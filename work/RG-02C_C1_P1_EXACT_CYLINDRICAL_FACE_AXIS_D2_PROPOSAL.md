## Product invariant — no operation-source dependency

One user-selected native bounded Face from the actual **result of the current Body stage** is the transient input. On a true analytic cylindrical surface the result is an infinite **unoriented** geometric line, even for a half-cylinder, partial arc patch, hole wall or eligible straight-edge Fillet. Do not use Extrude vectors, Revolve input axes, Fillet settings, sketch metadata, approximated triangles, a finite Face boundary, or the generating Feature kind to derive the axis. The same Face geometry must give the same geometric line regardless of operation history. Do not promise persistent Face identity across arbitrary topology edits; the selected native token is transient.

## Existing precise seams (main after P0)

- Native provider `src/kernel_occt/solid_modeling_kernel.cpp` has private `OcctRuntimeSolid::inventory_faces`, `bindFaceToBody`, and `queryFaceBoundaryImpl`. It checks **the same RuntimeSolidHandle pointer** as a bound `ScopedBoundaryFace`, then resolves the actual Face in that Body inventory. `providerSurfaceKind` already uses `BRepAdaptor_Surface(face,true).GetType()==GeomAbs_Cylinder`. **No public axis-origin/direction query exists.**
- Shared `src/kernel/include/simplesolid2/kernel/face_boundary.hpp` provides body-owned opaque Face binding, but only oriented contour observations. Shared `src/kernel/include/simplesolid2/kernel/exact_bounded_edge_geometry.hpp` models exact, typed, owner-scoped read-only Edge geometry; it is a useful **pattern**, not a Face API. `src/kernel/include/simplesolid2/kernel/solid_modeling.hpp` already defines `Axis3`, but it is **signed as a representation**, not a durable Axis source or geometric orientation authority.
- Part has stage-scoped `SurfaceReference{BodyStageRef,FeatureSurfaceAddress}` and a current `BodyFaceTopologyRecord::surface_candidates` set. A `FeatureSurfaceResolution` carrier may be `resolved` while `strict_face_status==ambiguous` because multiple bounded Face realizations share that same carrier. One picked Face and one durable semantic Surface carrier must **not** be treated as identical without an explicit proof/Owner design decision.

## Proposed P1-A, to accept explicitly before any code: exact native Face-axis query

**Goal:** one minimal provider-neutral, read-only query of **the current, bound, actual bounded Face** that returns an analytic cylinder's infinite line and radius or a typed fail-closed result. This is **not** Part Axis authoring, persistence, Revolve, UX, or selected Face→durable source design.

Proposed provider-neutral result: `ExactCylindricalFaceAxisResult{status, optional analytic_line, optional radius_mm}`. Line means `{point_on_axis_world, unoriented_unit_direction}`; the point is **any point on the same infinite line**, not a unique or persisted origin. Radius is finite and positive; line direction finite and nonzero, normalized. Signed Face orientation, cylinder parameterization, UV seam and the choice of axis-point origin **must not** change its unoriented geometric line. Never use signed axis direction as a Revolve Reverse default. Geometry equality must compare **collinearity and perpendicular line distance** within existing numerical policy, not `Point3` exact equality or signed vector equality.

Typed status candidates: `ok`, `invalid_input`, `provider_mismatch`, `face_unavailable`, `non_cylindrical_surface`, `invalid_cylinder`, `kernel_failure`. A default-constructed provider or wrong Body generation, stale/foreign scoped Face, planar/conical/toroidal Face, invalid radius, nonfinite position/direction and OCCT exception all fail closed: **no cached, approximate or guessed Axis**.

**D2 API choice to resolve before mutation:** prefer an **explicit read-only exact-Cylinder-Face capability** using a provider-minted Body-bound Face (either safely reuse existing `ScopedBoundaryFace` with a precisely justified additive interface method, or introduce a dedicated `ScopedExactFace`/interface by analogy with Q0). Select the smallest seam that preserves source-body provenance and does not turn `IFaceBoundaryQuery` into an unrelated mutating subsystem. Retain source type in `src/kernel/**`; OCCT `TopoDS_Face` and `gp_Cylinder` must not cross the provider-neutral boundary. Query from the actual mapped `TopoDS_Face` using `BRepAdaptor_Surface` / analytic `Cylinder()`, never from kernel-generated Feature intent. No new runtime cache.

**Provisional file-budget for Owner review, NOT an executable allowlist:** one minimal existing/new provider-neutral `src/kernel/include/simplesolid2/kernel/*` query contract, `src/kernel_occt/include/simplesolid2/kernel_occt/solid_modeling_kernel.hpp`, `src/kernel_occt/solid_modeling_kernel.cpp`, the **existing registered** `tests/kernel_native/pm04c2_production_revolve_test.cpp`, and one `work/**` evidence ledger. If another `src/**` or test file is technically necessary, STOP for exact Owner amendment before touching it. No UI, Part Axis source/variant, schema, CMake registration, CI workflow or `ACTIVE.yaml` changes in P1-A.

## Mandatory native witnesses, including real negatives

- Actual resulting Body Face analytic cylinder after complete circular Extrude and full Revolve; genuine trimmed cylindrical Face after partial Revolve and half-cylinder Boolean Cut. Query the **picked bounded Face**, not the producing Feature.
- Genuine analytic cylinder from a **straight-edge Fillet** is a separate desired positive witness; P0 had only a circular-rim Fillet. Propose a minimal native fixture if necessary **inside the already registered allowed test file**. If the needed geometry cannot be produced within that bound, report **GAP**, do not call torus `cylinder` or widen the allowlist silently.
- Negative: planar, toroidal and conical (where fixtures exist) explicitly refused; missing Face, stale or different Body, provider mismatch and numerical-token reuse; invalid/degenerate geometry and exception boundaries wherever safely injectable without test-only production seams.
- Test Face orientation and trim/partition invariance by comparing the **unoriented infinite line** and analytic radius under the actual native cases. Do not equate reversing `TopoDS_Face` orientation with a physical new axis sign or demand a signed orientation certificate.
- Reuse registered target, real Windows native FOCUSED → FAST → FULL Core/Kernel/Desktop and exact-head CLOSURE; record individual executed proof vs fixture gaps and Owner P1-A technical PASS separately. Do not claim any test ran from this proposal.

## P1-B and UX: explicit STOP after provider evidence

Only **after Owner-reviewed P1-A evidence**, design a Part-level admission from a user-picked Face and exact `BodyStageRef` to durable intent. A picked bounded Face can map to one semantic Surface carrier whose `current_faces` count is greater than one. The architecture must decide, with a native counterexample if possible, whether (a) strict singular Face is required, (b) a certified **entire analytic cylinder carrier** suffices even if partitioned, or (c) an additional durable bounded-patch discriminator is needed. Never persist `RuntimeFaceToken` or silently select an arbitrary patch. Report ambiguous/missing/noncylindrical Face failures as typed statuses; no nearest XYZ or equal-radius substitution. **This is NOT pre-approved by P1-A.**

Only then consult Owner on existing **Operations → Axis → Constructor: Cylindrical Face** selection, preview, Edit/Repair, CAD Command Line and directional conventions. Separate accepted UX, accepted product Work Contract, native writer/read-back and full lifecycle/REVOLVE/DOC-01 gates precede UI or Part mutation. The current `work/ACTIVE.yaml` still points to C1-P0 until a separately authorized closeout/activation.
