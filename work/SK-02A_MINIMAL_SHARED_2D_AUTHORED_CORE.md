# SK-02A — Minimal Shared 2D Authored Core

**Status:** PROPOSED  
**Decision class:** D2 semantic identity/model contract + implementation  
**Foundation:** 1.0 (`foundation-v1.0`)  
**Roadmap:** `work/SKETCH_ROADMAP.md` v1.0  
**Roadmap milestone:** R1 — Minimal Shared 2D authored core  
**Related ADRs:** ADR-0003, ADR-0005, ADR-0008

## 1. Goal

Implement the smallest real host-neutral Shared 2D authored model before any Part persistence, Viewer or interactive Sketch tool integration.

The vertical slice is deliberately semantic only:

```text
Sketch authored model
→ stable EntityId
→ finite 2D point coordinates
→ first Line entity
→ deterministic collection / lookup / validation
→ semantic tests
```

No UI can create or display the Line in SK-02A.

## 2. Proposed semantic decisions requiring Owner acceptance

### 2.1 EntityId

Each authored 2D entity has a stable opaque `EntityId`.

Proposed representation policy:

- canonical UUIDv4 text identity, consistent with current `DocumentId` and `SketchId`;
- generated by Shared 2D, not by UI/Viewer;
- stable when the authored model is copied/restored;
- never derived from collection index, draw order, geometry values, Viewer token or provider object;
- identity is interpreted in the owning Sketch model context; UUID representation does not make an entity a top-level Document.

Reason for UUIDv4 instead of a small reusable integer allocator: entity identity must not accidentally rebind after Undo/Delete/history branching or later Save/Reopen. A random opaque identity avoids requiring a persistent high-water allocation counter in the first model.

The exact implementation may share/refactor UUID mechanics only if doing so remains a bounded D1 cleanup and does not alter existing DocumentId/SketchId semantics.

### 2.2 Point2

Introduce the minimal Sketch-local 2D coordinate value:

```text
Point2
  u
  v
```

Rules:

- scalar storage is finite double precision;
- NaN and ±Inf are invalid authored coordinates;
- Point2 is geometry/value, not stable identity;
- no standalone authored Point entity is introduced;
- no unit-conversion framework or tolerance policy is introduced in SK-02A.

### 2.3 Line

The first authored entity is a finite line segment:

```text
Line
  EntityId
  Start : Point2
  End   : Point2
```

Rules:

- Start and End are independent authored endpoint sub-elements of that Line;
- endpoints of different Lines may have exactly equal coordinates without sharing identity;
- equal coordinates do not imply Coincident or another relation;
- an authored Line whose Start and End are exactly equal is invalid;
- no fuzzy/minimum-length tolerance is introduced yet;
- no authored midpoint exists;
- no constraint, dimension, construction role or sub-element public API is introduced.

A zero-length candidate may exist later as transient Tool preview, but it cannot enter the authored SK-02A model.

### 2.4 Authored model / collection

Introduce the smallest reusable Sketch authored entity container.

Required semantics:

- owns zero or more authored entities;
- each contained EntityId is unique;
- supports stable lookup by EntityId;
- preserves entity identity and geometry under value copy;
- supports Line as the only entity kind in this contract;
- does not expose collection index as semantic identity;
- does not infer connectivity merely from equal coordinates;
- invalid entities or duplicate IDs fail closed at any state-restoration/validation boundary that SK-02A introduces.

The exact internal container and C++ type layout are D1 implementation details inside this contract.

## 3. Scope IN

### Shared 2D target

Extend `simplesolid2_sketch` only with the minimum neutral authored model needed for R1:

- EntityId;
- Point2 / finite-coordinate validation;
- Line authored geometry;
- minimal entity/model collection and lookup;
- equality/value semantics needed by semantic tests;
- focused unit tests.

### Build/test

Register a dedicated R1 semantic regression in CTest.

The tests must compile without Qt and without OCCT.

## 5. Architecture boundaries

- `simplesolid2_sketch` must not depend on Part, Application, UI, Viewer, Qt, OCCT, persistence or filesystem APIs.
- Part remains the host owner of Sketch placement/support/lifecycle; SK-02A does not move those semantics into Shared 2D.
- EntityId must not be a Viewer/presentation token.
- Point coordinates are authored semantic geometry, not evaluated/provider geometry.
- Equal endpoint coordinates do not create connectivity or a relation.
- No tolerance, solver or constraint behavior may be smuggled into Line validation.
- No persistent mutation bypass is introduced; Document-level Command/Transaction integration belongs to R2.

If implementing R1 requires Part persistence, a public sub-element framework, standalone Point entities, tolerance policy, solver behavior or Viewer input, stop and amend the contract instead of expanding scope.

## 6. Acceptance tests

At minimum prove:

1. `simplesolid2_sketch` remains buildable without Qt/OCCT/Part dependencies.
2. EntityId generation produces valid canonical opaque IDs and parse/round-trip preserves identity.
3. malformed EntityId text fails closed.
4. Point2 accepts ordinary finite U/V coordinates.
5. Point2 rejects NaN and positive/negative infinity.
6. a Line with two distinct finite endpoints is valid authored geometry.
7. a Line with exactly equal Start and End is rejected.
8. two separate Lines may use endpoint coordinates that are exactly equal while retaining different EntityIds and independent endpoint values.
9. a model can contain multiple Lines and look each up by stable EntityId.
10. model lookup does not depend on insertion index.
11. duplicate EntityId state is rejected at any explicit restore/validation boundary introduced by this implementation.
12. copying the authored model preserves EntityIds and exact authored geometry.
13. no Part/Application/UI/Viewer/persistence dependency is introduced into the Sketch target.
14. existing complete CTest suite remains PASS.
15. exact-head Windows docs/verify/build/CTest gate is PASS.

## Documentation impact

Internal docs: required
User/Product docs: not required
Reason: SK-02A introduces the first real Shared 2D authored entity model and stable entity identity, but no user-visible Sketch drawing workflow yet exists.

Internal documentation must describe only the as-built R1 semantics and current limits. Product documentation must not claim that Line can already be drawn in the application.

## 7. Completion

SK-02A completes only when the neutral authored Line model and focused semantic regression are implemented, internal documentation is current and the exact-head Windows gate passes.

Completion does not activate R2 automatically. Part integration and persistence require a later explicit Work Contract.
