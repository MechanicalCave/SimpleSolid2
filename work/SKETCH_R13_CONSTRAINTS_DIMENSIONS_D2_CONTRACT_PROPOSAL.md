## 3. Proposed R13 user model — D3 OPTIONS REQUIRING OWNER FREEZE

**Recommended first-class distinction:**
- **Geometric relation** is an optional authored constraint, with stable `ConstraintId` and references by Sketch EntityId+semantic role. Snap/guides remain transient. Default **manual relations**; no Auto-Constraint on mere snap until separately accepted opt-in design.
- **Driving dimension** owns one numeric value as **a constraint** under ConstraintId; editing it solves dependent free geometry (never by direct unsynchronized coordinate rewrite). Model and UI display derived value from the accepted authored driving intent.
- **Reference dimension — OWNER ACCEPTED:** durable Sketch-owned `DimensionId`, distinct from Driving `ConstraintId`; its numeric value is a read-only measurement of accepted *evaluated* geometry and must not add a solver equation or reduce DoF. Native 3D Sketch Edit annotation has the **same select, drag-placement, Esc, Delete, Undo/Redo and cold Save/Reopen lifecycle** as Driving, but double-click cannot modify the measured number. **Driving↔Reference conversion is an explicit separate atomic action** with validation, never a side effect of selecting, editing text, dragging, or deleting.
- **Under-constrained** is legal. Display DoF / state without blocking ordinary Sketch finishing merely because DoF > 0. Conflicting, redundant, unsupported, stale or non-convergent attempted *new* constraint/dimension must reject atomically without corrupting the valid previous document. Distinguish conflicting from redundant rather than hiding either.
- **Local solve only**: choose free-variable motion respecting fixed/reference geometry and any valid constraints; cursor interaction and solver preview cannot persist derived geometry. Explicit authored coordinate/seed is retained and evaluated geometry is separately materialized.
- **Auto-Constraint**: recommend OFF by default for R13 v1; separate Owner-approved toggle and exact inference-to-relation semantics in later phase.
- **Dimension placement**: **mandatory user-controlled durable placement** of the dimension's label and dimension graphics in Sketch-local U/V coordinates, attached to stable semantic targets. Moving the annotation must **never** rebind references or modify the driving value, constrained geometry, solver DoF or entity/constraint IDs. The annotation is projected in the real 3D Part Sketch Edit viewer and remains attached under camera rotation, pan, zoom, recompute and reopen. Native hit/selection targets and screen DPI do not become authored identities. R8 read-only measurements remain separate.

### 3.1 Owner-mandated A2 native-viewport dimensions — D3 lifecycle contract proposal

**The Owner-mandated outcomes are non-optional for R13-A2:** a Driving dimension has (a) an immutable semantic attachment to the constrained geometry, (b) an authored driving value and (c) a **separately editable persistent annotation placement**. In the existing **3D CAD viewport while Sketch Edit is active**, render witness lines, dimension line/arrows, and a readable numeric label. User can **drag the annotation to a different location relative to the Sketch**, without detaching, changing its targets, changing the driving value or moving geometry. User can **edit that parameter by interacting directly with the displayed value label** in this same viewport. Moving/editing, Esc, Delete, Undo/Redo, document close, and cold reopen must have complete lifecycle support.

**D3 gesture semantics proposed for Owner freeze (the gesture choice is not yet a separate Owner decision):**

1. **Creation:** choose Dimension, acquire a supported semantic Line Length / Circle R / Circle D target, preview the entire attached dimension and its location in the 3D Sketch viewport, choose placement, type/accept value and commit once after a successful solve. No accepted preview is persisted or added to history. Existing same-kind Driving constraints must not be silently duplicated.
2. **Selection/hover:** one LMB on number, dimension line, arrow or extension witness selects the **dimension** by durable ConstraintId, not its Line/Circle. Context and hover identify the selected annotation unambiguously. Overlapping text/lines require deterministic hit-test cycling/priority and stable identity.
3. **Reposition:** LMB-drag the dimension label or its designated placement handle above the established drag threshold, previewing placement **only**; LMB release commits exactly one revision-bound `SetDrivingDimensionPlacement» transaction/Undo step. Cancel with Esc during drag: discard placement preview and preserve selection + all authored content. A click below threshold selects, not moves. **Semantic target IDs/roles, parameter value, entity coordinates and solver result stay identical**. Persist the placement intent in Sketch U/V, never an absolute screen-pixel position. Reproject correctly through Part Sketch support frame; text remains readable on 3D camera rotate/zoom/pan without changing its attachment.
4. **Direct edit on label:** double LMB on the **visible numeric label** opens a real accessible inline text entry anchored **at the label in the 3D viewer**; optionally Enter on a selected dimension may do the same. The input owns keyboard focus and uses the canonical SS2 quantity parser and unit rules. Enter on valid quantity invokes a single version/revision-checked semantic `EditDrivingDimensionValue» command; after accepted solve/residual check the dependent geometry, profile and applicable Part feature rebuild consistently, with one Undo entry. Equivalent same-value input = no authored change. **An Operations/toolbar value field may be auxiliary, never the only editor.**
5. **Invalid or conflicting input:** negative/nonpositive targets where forbidden, NaN/Inf, invalid units, solver Conflict/Redundant/Unsupported/NoConvergence/ResidualViolation, missing reference and stale revision author **nothing**, allocate no durable IDs, preserve the last accepted value/geometry and provide a visible diagnostic while allowing correction or Esc. Solver preview never authors history; no implicit commit on focus loss, pane/tool switch or document context change.
6. **Esc hierarchy and focus:** when inline text has focus, the **first Esc cancels only its pending value/preview**, restores previous committed dimension + geometry and returns focus to Sketch viewport; it **does not** Finish Sketch or delete/select another entity. With placement drag in progress, first Esc cancels only drag preview. In dimension acquisition, first Esc cancels only its uncommitted acquisition/placement. Only a subsequent Esc without an active dimension sub-operation follows the existing S3 Select/selection/Sketch Edit hierarchy. The global CAD-input Enter/Space/Esc router must not consume text-editor key presses; Enter only commits the valid local numeric editor. Cancel before Undo/Redo, tool switch, Save/Close or switching active Document — no hidden commit/preview leak.
7. **Delete/Backspace:** when the **inline text editor** owns focus, Delete/Backspace modify **characters** and do not remove the dimension. With viewport focus in idle Select, a selected Driving dimension and Delete remove **the Driving constraint plus its dimension presentation**, **never its referenced Line/Circle or Part Sketch**. One global Undo restores the exact constraint/label/placement identities and value, Redo removes them again. Esc never deletes an already authored dimension. Selecting *geometry* then Delete is a different A1 constrained-geometry deletion cascade with separate explicit contract.
8. **Delete Driving — OWNER-ACCEPTED D3 (2026-10-18):** deleting a selected Driving dimension removes only its associated driving constraint and annotation/presentation and **releases its degree(s) of freedom while preserving the last accepted solved geometry in place**. Example: removing the 50 mm length dimension leaves a Line measuring 50 mm but no longer controlled by that dimension. A single revision-checked semantic deletion Command atomically materializes the previously **validated evaluated** geometry into a durable *unconstrained authored seed* for the affected Sketch and removes the selected constraint/presentation. Surviving constraints must continue to pass the accepted solver residual policy; fixed/projected references cannot move, and unrelated relations or entities must not be removed. Undo restores the exact prior authored seed, ConstraintId, dimension presentation and geometric solution; Redo repeats deletion with one global history step. This is an **explicit authored deletion**, never a read-only recompute side effect. On stale revision, conflict, missing reference or residual violation: **reject atomically** with no partial update. Solver-derived DoF is reported, not guessed. Owner explicitly approved with `Tak, akceptuje - kontynuujmy`. **Deleting the underlying constrained geometry** is a separate A1 deletion-cascade policy, still requiring a D3 decision.
9. **Cold lifecycle:** placement relative to constrained Sketch, semantic references, value, graphic type/visibility and format survive Undo/Redo, Save→Close→**process restart**→Reopen, and updates to driving value or Sketch frame. UI selection/hover, text focus, active drag and solver cache are runtime-only and never persisted. An offscreen/occluded label cannot become an unselectable orphan; viewer pan/zoom/rotation, orthographic/isometric view, device DPI (100/125/150/200%) and input ownership are real native Windows acceptance.
10. **Reference (A3) — OWNER ACCEPTED:** the same attached and independently movable 3D dimension presentation, selection, Esc/Delete and durable history/persistence as Driving, but an independent `DimensionId` and read-only measured value. Its number cannot be edited through label double-click. **Convert to Driving** is a separate, named, solver-checked action. See §3.3.

**Source comparison (no donor parity claim):** the donor's `dimension_state.hpp` has `DimensionPresentationRecord` with Linear/Angular/Radial placement, and `SketchController` supports selection, numeric editing, Delete and Esc/Undo. In `SimpleSolid_Sketcher_Qt/src/sketch_editor_widget.cpp` the numeric `QLineEdit` lives in a **toolbar**, not directly on the label. Its existing code does not establish the Owner-required 3D in-place inline editor or draggable final label placement in SS2. The overlay/drag must therefore be separately designed and verified on the real SS2 Qt/OCCT viewer.

### 3.3 Reference dimension lifecycle and intentional conversion — OWNER-ACCEPTED D3

It is **not an active solver constraint**, imposes no Driving parameter and reduces no DoF. Text input owns Backspace/Delete as character operations. Camera pan/zoom/rotation and DPI do not change durable Sketch-relative placement.
- **Value freshness:** after valid geometry edits by other Driving constraints or accepted direct edits, Reference label recomputes its measured value but never mutates the Reference authored record, burns no IDs and creates **no additional revision, document dirty flag or Undo step** beyond the actual source edit. On invalid/failed evaluation, report failure instead of silently showing stale measurement as current.
- **Direct label:** a double-click on the Reference numeric label **must not** open an editable Driving value input, directly control geometry or silently convert intent. It may show a read-only inspection or an affordance to invoke an **explicit** conversion, while focus/Esc remain under the Sketch Edit hierarchy.

When accepted, create a Driving constraint initialized to the actual accepted measured quantity; preserve geometry, semantic targets, visible annotation placement and format; one revision-checked transaction / one Undo. Undo restores exactly the previous Reference record/ID/placement/geometry.
- **Convert Driving → Reference:** separately named command, releasing the Driving constraint and preserving the **last accepted solved geometry** according to Owner-approved §3.1(8), then making a Reference record with the same semantic targets/placement/format. Do not jump geometry or silently alter surviving constraints. A single revision-checked transaction and Undo/Redo.

### 3.5 Delete constrained Sketch geometry — OWNER-ACCEPTED D3 CASCADE + PART REPAIR (2026-10-18)

**Distinguish two operations:** Owner already accepted §3.1(8) Delete **Driving dimension** (remove only driving constraint/annotation, freeze last solved geometry). ### 3.6 Conversion identity and UI commands — D3 PROPOSAL / OWNER DECISION OPEN

**Prerequisite:** §3.3 already makes explicit deliberate Reference↔Driving conversion and atomic Undo mandatory. Neither the earlier Reference acceptance nor §3.5 cascade approval fixed exactly **how the two distinct ID namespaces and annotation selection behave**. This paragraph proposes the simplest tested donor-compatible model for an explicit separate Owner decision.

1. **Distinct durable owner IDs:** a Driving parameter's authoritative owner remains a `ConstraintId`, while a Reference annotation has its own `DimensionId`. On each accepted conversion, allocate exactly one **fresh destination-type** ID in its appropriate Sketch-local monotonic cursor; retire the source record and its old ID from the live state. **Never reinterpret/alias an old ConstraintId as DimensionId, or vice versa**. Undo restores the exact preconversion source record, ID, authored seed, attachment and placement; Redo recreates the accepted destination ID, not another fresh one.
2. **Preserved user meaning:** record semantic geometry target(s), Sketch-local label placement, format/precision/visibility and last accepted solved geometry continuously across conversion. The annotation *type* changes while the user-visible position and target do not. Selection targets the **new authoritative ID** after commit and the original ID after Undo; raw application pointers/Viewer handles do not survive the transaction. Never revive an ID to mean another unrelated dimension in the same Sketch history.
3. **Driving → Reference:** selected Driving annotation → dedicated context-menu/Operations action **Convert to Reference**. Remove its Driving solver constraint; as in approved Delete Driving freeze the *current validated solved* geometry into authored seed in the **same explicit transaction**, preserving constraints unrelated to this source. Create measured read-only Reference with fresh DimensionId; display same physical quantity with unchanged label placement. One revision, one Undo, no geometry jump, no silent extra edit.
4. **Reference → Driving:** selected Reference annotation → dedicated **Convert to Driving** action. Read the same-revision *accepted evaluated* measurement as the proposed initial Driving value; validate legal target kind, units, current Part frame/revision and constraints, duplicate/redundant/conflict/DoF/fixed-reference and finite residuals. If it cannot be enforced without violating remaining intent, **fail closed** with a diagnostic, leaving Reference record, placement and geometry unchanged. Otherwise replace it with Driving constraint under new ConstraintId, retaining visual placement. One revision, one Undo, deterministic cold persistence.
5. **Input grammar:** conversion is **never triggered** by hover, click, double-click numeric text, Enter after editing the label, pressing Delete or merely selecting a dimension. It is a consciously named operation available only on a selected applicable dimension through the established right Operations panel and/or context menu. On the selected read-only Reference label, double-click may show read-only information or a contextual hint, not an active editable numeric field.
6. **Cancellation and failures:** Esc on any modal confirmation/preview aborts conversion without changing either ID cursor, authored model, revision or history. Stale revision or loss of semantic target between selection and commit rejects atomically. Neither conversion mutates an upstream projected entity, auto-creates a profile or updates global part dependencies outside the legal DocumentSession transaction.
7. **Registered RED native tests:** Convert R→D valid line length/Circle R with same shape/label position, duplicate/conflict/projection rejection, IDs swapped by typed namespace, undo/redo stable with exact one-command semantics; Convert D→R with last-solved seed, unchanged body/profile, cold save/reopen; 3D focus/selection/Operations/ESC guards; compatibility with the approved §3.5 cascade where deleting a referenced entity removes whichever typed dimension now owns the target.

**Source compatibility:** donor `SimpleSolid` SketchController implements separate `convertSelectedDrivingDimensionToReference()` / `convertSelectedReferenceDimensionToDriving()` paths and new destination IDs plus placement/format transfer. **That code is a guide only**; SS2's single Application DocumentSession and strict native persistence remain authoritative.

**Owner D3 decision requested next:** accept the **fresh destination-type ID + source ID retired, Undo restores, placement retained, deliberate context/Operations command** conversion model, or propose a different identity model. This choice does **not** approve R13-A3 implementation by itself.
