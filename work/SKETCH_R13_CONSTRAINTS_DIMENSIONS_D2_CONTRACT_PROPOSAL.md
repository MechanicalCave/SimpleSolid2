## 3. Proposed R13 user model — D3 OPTIONS REQUIRING OWNER FREEZE

**Recommended first-class distinction:**
- **Geometric relation** is an optional authored constraint, with stable `ConstraintId` and references by Sketch EntityId+semantic role. Snap/guides remain transient. Default **manual relations**; no Auto-Constraint on mere snap until separately accepted opt-in design.
- **Driving dimension** owns one numeric value as **a constraint** under ConstraintId; editing it solves dependent free geometry (never by direct unsynchronized coordinate rewrite). Model and UI display derived value from the accepted authored driving intent.
- **Reference dimension** owns separate `DimensionId`, is durable and read-only as geometric control; its measured value updates from evaluated geometry. Driving/Reference conversion must be explicit, validated and one atomic transaction, never silent.
- **Under-constrained** is legal. Display DoF / state without blocking ordinary Sketch finishing merely because DoF > 0. Conflicting, redundant, unsupported, stale or non-convergent attempted *new* constraint/dimension must reject atomically without corrupting the valid previous document. Distinguish conflicting from redundant rather than hiding either.
- **Local solve only**: choose free-variable motion respecting fixed/reference geometry and any valid constraints; cursor interaction and solver preview cannot persist derived geometry. Explicit authored coordinate/seed is retained and evaluated geometry is separately materialized.
- **Auto-Constraint**: recommend OFF by default for R13 v1; separate Owner-approved toggle and exact inference-to-relation semantics in later phase.
- **Dimension placement**: **mandatory user-controlled durable placement** of the dimension's label and dimension graphics in Sketch-local U/V coordinates, attached to stable semantic targets. Moving the annotation must **never** rebind references or modify the driving value, constrained geometry, solver DoF or entity/constraint IDs. The annotation is projected in the real 3D Part Sketch Edit viewer and remains attached under camera rotation, pan, zoom, recompute and reopen. Native hit/selection targets and screen DPI do not become authored identities. R8 read-only measurements remain separate.

**Owner-accepted D3 direction:** the staged R13-G0→A1→A2→A3 delivery, manual constraints/Auto-Constraint OFF, and §3.1 viewport editing + placement + Esc/Delete requirements below. **Remaining Owner D3 design decisions OPEN (recommended defaults in parentheses):**
1. Minimum first shipping relation family: **Coincident(endpoint-endpoint), Horizontal(Line), Vertical(Line), Parallel(Line-Line), Perpendicular(Line-Line)** (YES); Tangent/Equal/Midpoint/Concentric delayed until tests validate R12 interaction (YES).
2. Minimum first shipping driving dimension family: **Line Length, Circle Radius, Circle Diameter** (YES); optional Point-Point horizontal/vertical and Angle staged later; current Sketch Arc radius included only after closed design for its direction/sweep role (DEFER).
3. Separate durable Reference dimensions, not solver constraints (YES); explicit Driving↔Reference conversion in later phase (YES).
4. **Auto-Constraint OFF** / manual relations first (**accepted**). Native 3D Sketch Edit dimension annotation and on-label edit (**mandatory**). Precise toolbar/Operations secondary controls and native overlay implementation remain for D3 review, but a toolbar-only text field cannot satisfy A2.
5. PlaneGCS (preferred **candidate**, not decided vendor/import) vs own reference solver or alternative: **independent native numerical and licensing G0 proof before approval**.
6. On existing unconstrained Sketch edit: preserve behavior and identity; no automatic inferred relations or geometry movement (YES).
7. Deleting constrained geometry: prefer **explicit dependent constraint + dimension cascade with one-command deletion, user-visible affected count**; unsupported structural Trim/Extend relationship outcomes reject or deliberately remove affected relations per exact future contract, never dangle.

### 3.1 Owner-mandated A2 native-viewport dimensions — D3 lifecycle contract proposal

**The Owner-mandated outcomes are non-optional for R13-A2:** a Driving dimension has (a) an immutable semantic attachment to the constrained geometry, (b) an authored driving value and (c) a **separately editable persistent annotation placement**. In the existing **3D CAD viewport while Sketch Edit is active**, render witness lines, dimension line/arrows, and a readable numeric label. User can **drag the annotation to a different location relative to the Sketch**, without detaching, changing its targets, changing the driving value or moving geometry. User can **edit that parameter by interacting directly with the displayed value label** in this same viewport. Moving/editing, Esc, Delete, Undo/Redo, document close, and cold reopen must have complete lifecycle support.

**D3 gesture semantics proposed for Owner freeze (the gesture choice is not yet a separate Owner decision):**

1. **Creation:** choose Dimension, acquire a supported semantic Line Length / Circle R / Circle D target, preview the entire attached dimension and its location in the 3D Sketch viewport, choose placement, type/accept value and commit once after a successful solve. No accepted preview is persisted or added to history. Existing same-kind Driving constraints must not be silently duplicated.
2. **Selection/hover:** one LMB on number, dimension line, arrow or extension witness selects the **dimension** by durable ConstraintId, not its Line/Circle. Context and hover identify the selected annotation unambiguously. Overlapping text/lines require deterministic hit-test cycling/priority and stable identity.
3. **Reposition:** LMB-drag the dimension label or its designated placement handle above the established drag threshold, previewing placement **only**; LMB release commits exactly one revision-bound `SetDrivingDimensionPlacement» transaction/Undo step. Cancel with Esc during drag: discard placement preview and preserve selection + all authored content. A click below threshold selects, not moves. **Semantic target IDs/roles, parameter value, entity coordinates and solver result stay identical**. Persist the placement intent in Sketch U/V, never an absolute screen-pixel position. Reproject correctly through Part Sketch support frame; text remains readable on 3D camera rotate/zoom/pan without changing its attachment.
4. **Direct edit on label:** double LMB on the **visible numeric label** opens a real accessible inline text entry anchored **at the label in the 3D viewer**; optionally Enter on a selected dimension may do the same. The input owns keyboard focus and uses the canonical SS2 quantity parser and unit rules. Enter on valid quantity invokes a single version/revision-checked semantic `EditDrivingDimensionValue» command; after accepted solve/residual check the dependent geometry, profile and applicable Part feature rebuild consistently, with one Undo entry. Equivalent same-value input = no authored change. **An Operations/toolbar value field may be auxiliary, never the only editor.**
5. **Invalid or conflicting input:** negative/nonpositive targets where forbidden, NaN/Inf, invalid units, solver Conflict/Redundant/Unsupported/NoConvergence/ResidualViolation, missing reference and stale revision author **nothing**, allocate no durable IDs, preserve the last accepted value/geometry and provide a visible diagnostic while allowing correction or Esc. Solver preview never authors history; no implicit commit on focus loss, pane/tool switch or document context change.
6. **Esc hierarchy and focus:** when inline text has focus, the **first Esc cancels only its pending value/preview**, restores previous committed dimension + geometry and returns focus to Sketch viewport; it **does not** Finish Sketch or delete/select another entity. With placement drag in progress, first Esc cancels only drag preview. In dimension acquisition, first Esc cancels only its uncommitted acquisition/placement. Only a subsequent Esc without an active dimension sub-operation follows the existing S3 Select/selection/Sketch Edit hierarchy. The global CAD-input Enter/Space/Esc router must not consume text-editor key presses; Enter only commits the valid local numeric editor. Cancel before Undo/Redo, tool switch, Save/Close or switching active Document — no hidden commit/preview leak.
7. **Delete/Backspace:** when the **inline text editor** owns focus, Delete/Backspace modify **characters** and do not remove the dimension. With viewport focus in idle Select, a selected Driving dimension and Delete remove **the Driving constraint plus its dimension presentation**, **never its referenced Line/Circle or Part Sketch**. One global Undo restores the exact constraint/label/placement identities and value, Redo removes them again. Esc never deletes an already authored dimension. Selecting *geometry* then Delete is a different A1 constrained-geometry deletion cascade with separate explicit contract.
8. **Delete geometry policy — OPEN FOR OWNER:** recommend that deleting a Driving dimension/constraint **releases that degree of freedom without moving the currently accepted geometry**. The deletion Command atomically captures last *accepted evaluated* coordinates as unconstrained authored seed, then removes the constraint and presentation. Undo restores old seed/constraint and exact solved display. This is **an explicit authored delete action**, not a recompute side effect. If this cannot be done while respecting other constraints, reject atomically. Owner must explicitly confirm or change this specific behavior before implementation.
9. **Cold lifecycle:** placement relative to constrained Sketch, semantic references, value, graphic type/visibility and format survive Undo/Redo, Save→Close→**process restart**→Reopen, and updates to driving value or Sketch frame. UI selection/hover, text focus, active drag and solver cache are runtime-only and never persisted. An offscreen/occluded label cannot become an unselectable orphan; viewer pan/zoom/rotation, orthographic/isometric view, device DPI (100/125/150/200%) and input ownership are real native Windows acceptance.
10. **Reference (A3):** identical select/relocate/Esc/Delete and durable attachment for a Reference dimension, with independent DimensionId, **but its value is read-only**. Double-click must not quietly turn Reference into Driving; explicit validated conversion is a distinct command.

**Source comparison (no donor parity claim):** the donor's `dimension_state.hpp» has `DimensionPresentationRecord» with Linear/Angular/Radial placement, and `SketchController» supports selection, numeric editing, Delete and Esc/Undo. In `SimpleSolid_Sketcher_Qt/src/sketch_editor_widget.cpp» the known numeric `QLineEdit» lives in a **toolbar**, not directly on the label. Its existing code does not establish the Owner-required 3D in-place inline editor or draggable final label placement in SS2. The new overlay/drag must therefore be separately designed and verified on the real SS2 Qt/OCCT viewer, rather than claimed inherited.

## 5. Hard technical acceptance criteria for every R13 product phase

1. IDs: no rebind by coordinates, nearest geometry, point-array index, runtime pick token or kernel Handle; stable EntityId/ConstraintId/DimensionId and replay-safe cursors; rejected/preview operations burn no durable IDs.
2. Solve: finite inputs, explicit caller-owned length/angular tolerances, residual acceptance for every constraint and fixed entity, deterministic diagnosis (Converged, Conflict, Failed/NoConvergence, Unsupported/ResidualViolation), DoF where valid; test contradictions, redundant relation, singularity, zero-length Line, nonpositive radius, angle/units, solver divergence.
3. Durability: authored constraints/parameters do not change on read-only recompute. No silently persisted solved coordinates, derived graph, solver cache, native BRep or presentation. Existing `.ss2part` reads migrate under explicit version. Multi-session/Undo/Redo/reopen preserve identity and selected semantics.
4. Transaction: every accepted Add/Edit/Delete/Convert is one revision-checked Command/Transaction/Undo, no preview history; Esc/focus/Cancel and stale editing do not alter accepted source. One stored PartSketch state remains authoritative.
5. Cross-subsystems: derived solved geometry goes to Sketch presentation, OSNAP, measurement, region/Profile, Part Extrude/Revolve only after solver acceptance; fail closed before Kernel when invalid, preserve good upstream last-authored state and diagnostics; projected/reference entities remain immutable.
6. UX: **all §3.1/§3.2 native 3D viewport label-edit / drag-placement / Esc/Delete / focus / Undo/Redo / cold-reopen cases are mandatory**. Explicit relation/dimension acquisition grammar and selected-object context; OSNAP glyphs never become constraints silently. Distinguish constraint glyphs, Driving and Reference hit-testing and edit permissions. Existing Part Work Features Axis and Sketch Part reference Axis remain separate.
7. Performance: measure live preview/solve/recompute and repeat single-Line authoring with simple and feature-heavy Part; set **numeric budget only after G0 measured baselines and Owner approval**, never hide a slow full-body recompute behind an unsupported benchmark claim.
8. Test-first: actual registered Windows RED before fixes, never weaken pre-R13 S0–S3 native 199-case suite, focused + FAST + full three target families, native cold persistence, owner UI workflows, docs/browser generator no diff and independent technical gate.
