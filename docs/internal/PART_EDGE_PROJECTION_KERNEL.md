## Geometry-only query

`kernel::IEdgeProjectionQuery` is the provider-neutral, read-only boundary for exact 3D Edge-to-Sketch-plane projection. The OCCT provider is `kernel_occt::OcctSolidModelingKernel`. Success returns `kernel::Curve2` containing exactly one Line2, Circle2 or Arc2 in the target Frame3 (mm and radians). This API does **not** author Sketch entities, Profiles, dependency links, Part schema or UI.

<!-- section-id: internal.part-edge-projection-kernel.identity -->
## Evaluation-local ownership

An unscoped `RuntimeEdgeToken` integer can recur in different OCCT runtime Bodies. First resolve the chosen source Edge against the *current strict Part stage*, then call `bindEdgeToBody(sourceBody, currentEdgeToken)`. This validates current provider inventory membership and produces an opaque, runtime-only `ScopedProjectionEdge`; its captured source Body remains alive.

`projectEdgeToPlane(currentBody, boundEdge, targetFrame)` accepts the binding only when the provided Body object is **identical** to the one captured. Passing an old scoped Edge with a new Body fails `provider_mismatch` even if raw token integers collide. Scope objects and raw tokens are **never persistent topology identity**. The caller must not hand `bindEdgeToBody` a stale integer from another source: the capture method cannot distinguish coincident bare numeric values. The implemented PG-01B/C/D Part and application paths **first** author or re-resolve a strict `BodyStageRef + MaterialEdgeReference` on the current stage, then bind the resolved runtime Edge. No geometry-nearest or traversal-order rebinding.

<!-- section-id: internal.part-edge-projection-kernel.geometry -->
## OCCT geometric rules

The provider looks up the current `TopoDS_Edge` and reads `BRepAdaptor_Curve`. Exact world-to-Sketch point projection is a dot product with target Frame3 U/V. The target frame must be right-handed **orthonormal**, checked against `Precision::Angular()` in addition to the general `Frame3::valid()`.

An OCCT Line produces oriented 2D endpoints; projection collapsing below `Precision::Confusion()` is `degenerate_projection`. Circular images require source and target normals parallel/anti-parallel within `Precision::Angular()`; otherwise their generally elliptical images are `unsupported_curve`. Full circle produces Circle2; a bounded circular Edge produces Arc2 with correct signed sweep, reversed orientation and periodic-seam crossing. Other OCCT curve kinds are `unsupported_curve`; **no tessellated or approximate replacement**.

<!-- section-id: internal.part-edge-projection-kernel.failure -->
## Status and current limits

`EdgeProjectionStatus`: `ok`, `invalid_input`, `provider_mismatch`, `edge_unavailable`, `unsupported_curve`, `degenerate_projection`, `kernel_failure`. Failures contain no curve. OCCT work is executed inside the provider-internal `detail::guardedExactEdgeProjection()` exception boundary, which maps both `Standard_Failure` and unexpected C++ exceptions to `kernel_failure` with **no curve**. The same guarded callable is exercised via the existing OCCT-native `profile_face_evidence.cpp` adapter with deliberate `throw Standard_Failure(...)` and `std::runtime_error`. The headless test reads provider-neutral typed evidence and does not include OCCT headers or expose a fault-injection switch in the projection API. This kernel seam alone does not implement associativity, derived Sketch views, Face boundary capture, Break Link, Save/Reopen, UI or Assembly; the separate **implemented PG-01B/C/D** Part/application/Workbench layers listed below own those bounded responsibilities.

## RG-02B1/D2-Q0 — exact bounded analytic 3D Edge geometry (implementation under test)

The separate provider-neutral `kernel::IExactBoundedEdgeGeometryQuery` is declared in `src/kernel/include/simplesolid2/kernel/exact_bounded_edge_geometry.hpp`, implemented by `kernel_occt::OcctSolidModelingKernel`. It does **not** extend or alter the existing 2D `IEdgeProjectionQuery`, nor implement the eventual Edge-local durable END reference, Datum Plane construction, signed Frame3, persisted schema or UI. This Q0 interface returns current **3D** observations only.

Part callers must **first** authorize `BodyStageRef + MaterialEdgeReference` against the exact current, strict Part stage, resolve the unique current `RuntimeEdgeToken`, and then use `bindExactEdgeToBody(sourceBody, currentEdge)`. An opaque `ScopedExactEdge` captures the precise runtime `RuntimeSolidHandle` object. `queryExactBoundedEdge3d(currentBody, boundEdge)` requires the SAME object and provider inventory. A repeated numeric token in another Body or cold provider does not restore identity; raw tokens, native Vertex index and XYZ must never be persisted as authored sources.

The OCCT seam inspects the real current `BRepAdaptor_Curve` of one inventoried Edge, and accepts **only** finite nondegenerate bounded `GeomAbs_Line` and genuinely open trimmed `GeomAbs_Circle` arcs. Observations contain the two Edge-owned native `TopoDS_Vertex` positions, **paired** with the corresponding current analytic trim tangent **lines without meaningful ± sign**, exact bounded length in millimeters, and analytic point/tangent at **half the bounded 3D length**. For a certified Circle this metric is `radius * (last - first)` (radians × mm); for a Line the bounded metric is analytic endpoint distance. Because OCCT native Vertex positions can differ from the analytic carrier within kernel tolerance, those observations must be validated against their own bounded carrier, without using their raw arithmetic average to define a distinct analytic MID. Native terminal array order is deliberately **not** a stable END key, and no sign of the analytic derivative becomes an authored plane normal.

N1a provisional numeric policy: `Precision::Confusion()` is a model-space length threshold, `Precision::Angular()` is an angular threshold, and each physical endpoint is validated against its current analytic boundary with `max(Precision::Confusion(), BRep_Tool::Tolerance(Vertex), BRep_Tool::Tolerance(Edge))`. Carrier-to-Vertex pairing must be unambiguous **within that current Edge**; two fitting assignments, collapsed/open-gap-below-tolerance geometry, nonfinite data, zero derivative or foreign Body fail closed. A true full/closed circle is rejected; a tiny but distinct open near-full circle is assessed using physical END gap/tolerances, never silently converted to full topology. A native derivative is evaluated with its own parameter units, not compared against an unrelated length epsilon.

The exact query returns `ExactEdge3dResult` with eight statuses: `ok`, `invalid_input`, `provider_mismatch`, `edge_unavailable`, `unsupported_curve`, `closed_or_periodic`, `degenerate_edge`, `kernel_failure`. Only `ok` contains complete geometry; no failure contains partial observations. `detail::guardExactBoundedEdge3dResult` is the **same exception guard called by the production provider implementation and by an injected generic C++ `std::runtime_error` test** in registered `pm02p.e_kernel_lifecycle`. An injected new-Q0 OCCT `Standard_Failure` is **NOT DIRECTLY TESTED** and is never credited from the separate PG-01A legacy 2D guard.

The existing registered `pm02p.e_kernel_lifecycle` is extended to assert real bounded 3D Line, open positive/negative/seam-crossing Arc, true closed-Circle rejection, cross-Body stale-scope denial, generic injected exception conversion and success passthrough. Registered `pm05c2b.part_edge_topology` verifies strict Part-stage semantic author/resolve **before** runtime binding, new cold independent provider and edited height evaluation without treating matching XYZ/tokens as source authority. **At the time of this documentation commit, these new Q0 native tests and Windows build are PENDING; they are not claimed PASS.** E0 older 199/199 Windows tests and §2C design/activation governance do not establish this 3D API's observed correctness.

## PG-01D — exact read-only native planar Face wire boundary

The optional provider-neutral `kernel::IFaceBoundaryQuery` is defined in `src/kernel/include/simplesolid2/kernel/face_boundary.hpp`, implemented by `kernel_occt::OcctSolidModelingKernel`. A `ScopedBoundaryFace` is bound to the **exact runtime Body object** plus one current `RuntimeFaceToken`; the query fails `provider_mismatch` against another Body generation, even if numeric topology tokens recur. OCCT reads the actual bounded planar `TopoDS_Face` wires and their oriented `TopoDS_Edge` *uses* (exact outer plus inner/hole wires). The provider never obtains boundary members by mesh/tessellation, Surface similarity or Viewer outline. A nonplanar Face or malformed wire accounting is rejected as a typed native status; no geometry repair.

`part::inspectMaterialFaceBoundary` in `src/part/feature_evaluation.cpp` cross-checks this answer against the **complete material Edge catalog from the same FeatureEvaluation and Body stage**. Strict bounded `BodyFaceTopologyRecord::semantic_address` is required; a merely selectable or Sketch-supportable `Surface` carrier is not enough. Each wire Edge must resolve through the established `authorMaterialEdgeReference`: reject seam, nonmaterial representation partition, missing or ambiguous Edge meaning, duplicate/repeated unsound semantic references and topology inventory/provider failure. Any **semantic or wire-integrity** failure rejects the entire Face. Successful `MaterialFaceBoundaryAdmission` has one bounded Face observation and oriented outer/hole Edge uses whose only durable candidates are individual `MaterialEdgeReference` values. A Face/wire number/runtime token is never written into the Part v15 schema.

## Owner-approved manual multi-Face Boundary — current native read and Workbench scope

The accepted later Owner D2 decision in `work/PROJECTION_01D_FACE_BOUNDARY_EXTENSION_AMENDMENT.md` replaces the experimental automatic contiguous-region traversal goal: **Face Boundary now adds exactly each individually clicked current bounded Face**, planar or nonplanar, to the existing Project Geometry draft. It does not infer adjacent Faces from common Surface/coplanarity, find an outer perimeter of their union, or cancel an authorable material Edge shared by two selected Faces. That true shared Edge is deduplicated once by strict same-stage `MaterialEdgeReference`. A periodic seam or representation partition is excluded only when the complete Part catalog explicitly certifies it as known nonmaterial. Distinct source Edges are never combined by geometric equality. Existing Edges and strict **single Planar Face** modes remain separate.

Provider-neutral `IFaceBoundaryQuery::queryFaceBoundaryAnySurface` (implemented by native OCCT) reads the exact current `ScopedBoundaryFace` outer and inner oriented wires without the old planar-only type restriction. `part::inspectSelectedFaceBoundary` binds that observation to one current FeatureEvaluation/Body catalog. It preserves all signed native wire uses in a **transient** ledger and maps every authorable material Edge independently; known nonmaterial seams may appear twice with opposite native uses. Missing directed Vertex evidence, incomplete native wire accounting, ambiguous/nonmaterial-but-uncertified Edge identity and provider/stage mismatch are integrity failures, **not** geometric Unsupported members. A durable strict semantic Face address is unnecessary for this clicked bounded runtime Face; nothing from the Face token/wire list is serialized. `part::inspectMaterialFaceBoundary` and the original planar-only provider query retain their older strict rules.

## PG-01D — three acquisition modes, same exact Edge source command

### Owner D2-V16 — production candidate identity and native persistence (2026-10-10)

The Owner approved the narrowly scoped `AtSingleSemanticPoint{FeaturePointAddress}` variant of `MaterialEdgeReference` under `BodyStageRef + FeatureCurveAddress`, with **no batch or automatic migration of existing native Part files**. Source meaning is associative option A: preserve the exact semantic source across supported upstream changes, but only with unique current resolution at the authored stage. A complete current stage and a multi-realization Curve are mandatory; the material Edge has two distinct native incident vertices and **exactly one** independently resolved/certified semantic Point endpoint. If another resolved Point could give a legacy two-Point alias, or if the Curve/Point/incidence is missing or ambiguous, the new resolver rejects rather than choosing provider order, geometry, proximity, last-good, or a prefix stage.

`part::authorProjectedMaterialEdgeReference` is exclusively a fallback for Project Geometry **Edges, Planar Face and Face Boundary**. The legacy `authorMaterialEdgeReference` path remains responsible for Fillet/Chamfer input, and a direct one-Point Fillet/Chamfer reference is structurally rejected. The Project Geometry UI enables the new authoring only while its one existing tool is active; selected source references still flow to one atomic `CreateProjectedSketchEdgesCommand`, deduplicated by exact semantic identity. Transient Face/wire/token membership is never serialized.

`PartDocumentStore::current_schema_version` is **16**. Recursive native parsing carries the enclosing schema version through nested Surface, Curve, Point and material Edge provenance, rejects new discriminants even deep inside v1–v15 files, and validates strict structure in v16. Historic readers retain their meaning. An explicit Save writes v16; merely loading older native bytes does not convert them. No bulk migration utility or automatic backfill exists. Cold Save/Reopen with a fresh provider, mixed-identity collision refusal, negative schema-version tests, dependent edits and Undo/Redo are required evidence, **not waived by this D2 approval**.
